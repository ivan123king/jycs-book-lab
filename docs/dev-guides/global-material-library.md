# 书库素材库指南

本文定义书库素材库的职责和边界。书库素材库是书库级入口，聚合书库中仍存在的单书素材引用，并保存书库自己的正式素材数据。

## 目的

书库素材库用于跨书检索和沉淀用户已经积累的写作素材。

它回答的问题是：

```text
我在这个书库里积累了哪些可复用写作素材
```

书库素材库不直接替代小说内素材模块。小说内素材模块规则见 `docs/dev-guides/book-material-library/implementation.md`。

## 数据来源

书库素材库的数据来源有两类：

1. 单书素材引用：仍在当前书库中的小说项目，其 `materials/materials.json` 和 `materials/texts/*.txt` 作为实时引用展示。
2. 书库自有素材：用户在书库素材页手动新建的素材，或移除书籍前由单书素材迁移出来的素材。

单书素材引用不复制正文；它仍以单书项目目录为正式数据源。书库自有素材是书库目录中的正式数据，不依赖任何单本小说存在。

## 正式存储

书库自有素材保存在书库根目录下：

```text
library-root/
  materials/
    library-materials.json
    texts/
      library-material-20260825-0001.txt
```

`library-materials.json` 示例：

```json
{
  "version": 1,
  "items": [
    {
      "id": "library-material-20260825-0001",
      "sourceMode": "migratedBookCopy",
      "bookId": "book-20260824-001",
      "bookName": "某本小说",
      "originalBookPath": "D:/library/books/book-20260824-001",
      "bookMaterialId": "material-20260824-0001",
      "materialType": "writingTechnique",
      "planTypeName": "人物感情",
      "dimensionName": "情绪变化",
      "title": "动作压住情绪的迟疑写法",
      "summary": "她把信收进外套。",
      "contentPath": "materials/texts/library-material-20260825-0001.txt",
      "tagIds": ["动作", "克制"],
      "sourceRefs": [],
      "createdAt": "2026-08-24T10:35:00+08:00",
      "updatedAt": "2026-08-25T09:10:00+08:00",
      "migratedAt": "2026-08-25T09:10:00+08:00"
    }
  ]
}
```

原则：

1. 书库自有素材的拆解说明必须保存为 TXT。
2. 书库自有素材随书库目录迁移，不放在应用系统数据目录作为唯一数据源。
3. 单书素材引用仍从单书项目目录读取，删除或编辑应回到小说内素材页处理。
4. `sourceMode=libraryOwned` 表示用户直接在书库素材页新建。
5. `sourceMode=migratedBookCopy` 表示移除书籍前从单书素材迁移为书库自有素材。
6. 应保留 `bookId`、`bookName`、`originalBookPath`、`bookMaterialId` 和 `sourceRefs` 快照，用于来源追溯和人工辨认。

## 页面职责

书库素材库属于书库级页面，不依赖当前是否打开某一本书。

页面职责：

1. 聚合展示当前书库中的单书素材引用和书库自有素材。
2. 支持按书籍、素材类型、标签和关键词筛选。
3. 支持分页查询，默认每页 50 条，避免上千条素材一次性渲染。
4. 支持查看标题、拆解类型、维度、原文、拆解说明和标签。
5. 支持手动新增书库自有素材。
6. 支持编辑和删除书库自有素材。
7. 对单书素材引用，只支持查看和打开来源书，不在书库页直接删除。
8. 对已迁移素材，允许作为书库自有素材继续编辑和删除。

书库素材库不负责：

1. 不把仍存在的单书素材复制成第二份正式数据。
2. 不自动跨书合并相似素材。
3. 不引入 AI 自动整理、云同步或账号系统。

## 移除书籍时的素材迁移

当用户从书库移除一本书时，必须先执行素材迁移，再删除单书项目目录。

迁移流程：

1. 读取待移除小说项目中的 `materials/materials.json`。
2. 读取每条素材的 `contentPath` TXT 正文。
3. 为每条尚未迁移过的素材创建书库自有素材。
4. 保留原素材的标题、原文、拆解说明、标签、拆解类型、维度和来源快照。
5. 将 `sourceMode` 写为 `migratedBookCopy`。
6. 迁移成功后才允许删除小说项目目录。
7. 如果迁移失败，必须中止移除书籍，避免素材丢失。

这样书库素材页在书籍仍存在时展示实时引用；书籍被移除后，原本的本书素材会变为书库正式素材，不会因为项目目录删除而失效。

## 性能规则

书库素材可能达到上千条，页面实现必须遵守：

1. 前端只渲染当前页数据。
2. 筛选、搜索和分页参数由后端统一处理。
3. 顶层提供刷新入口，用于重新扫描书库中仍存在的单书素材。
4. 列表卡片只展示摘要信息，完整原文和拆解说明放在详情弹框。
5. 后续如素材规模继续扩大，可以在书库目录中增加可重建索引缓存，但不能取代正式 JSON 和 TXT。

## 边界

第一阶段不做：

1. 自动跨书合并相似素材。
2. AI 自动整理素材。
3. 云同步或账号系统。
4. 多人协作素材库。
5. 复杂跨书比较和可视化。
