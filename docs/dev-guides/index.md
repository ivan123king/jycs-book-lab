## 文档索引维护

后续新增任何 `docs` 文档时，必须同步更新本文索引。

新增文档需要写清：

1. 文档路径。
2. 文档用途。
3. 哪类任务需要先阅读该文档。

不要让新的指南文档脱离索引单独存在。后续 AI 只应从本文开始寻找需要阅读的开发文档。

## 模块边界

本项目功能分为两大类：

1. 页面模块：负责 PC 端界面、阅读交互、表单配置、素材管理和分析呈现。
2. 后端模块：负责本地文件导入、章节识别、本地存储、数据模型、业务规则和搜索查询。

页面模块不要直接承担复杂数据持久化逻辑。后端模块不要绑定具体 UI 表现。

## 第一阶段功能模块

P0 只围绕完整闭环开发：

1. 书库模块
2. 小说导入与章节识别模块
3. 阅读与正文编辑模块
4. 选文拆解模块
5. 拆解方案配置模块
6. 素材库模块
7. 分类与标签模块
8. 来源追溯模块

暂不主动开发跨书比较、复杂图表、AI 自动分析、云同步、账号系统。

## 修改前检查

每次开发前确认：

1. 任务属于哪个模块。
2. 是否影响书籍、章节、原文片段、拆解卡片、素材之间的关系。
3. 是否需要更新本地数据结构。
4. 是否需要迁移旧数据。
5. 是否会增加用户填写成本。
6. 是否破坏阅读优先和选文优先原则。

## 提交前检查

每次修改后确认：

1. 页面和后端职责没有混在一起。
2. 新增文件有文件注释。
3. 新增模块有模块注释。
4. 新增导出函数或复杂函数有函数注释。
5. 关键业务逻辑有功能注释。
6. 新增字段能解释其业务含义。
7. 本地数据读写有错误处理。
8. 不需要的抽象、框架和依赖没有被引入。
