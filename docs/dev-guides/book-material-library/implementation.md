# 小说内素材模块指南

本文定义小说内素材模块的产品目的、页面交互、数据结构和实现边界。小说内素材是当前小说项目目录中的正式数据，它只展示和管理从当前小说沉淀出的素材，不负责跨书聚合。

## 目的

小说内素材用于把当前书中的写作手法拆解和剧情拆解沉淀成可复用写作知识。

素材回答的问题不是“这段原文我怎么分析”，而是：

```text
我以后写作时可以复用什么经验、套路、表达方法或剧情结构
```

素材可以来自：

1. 写作手法拆解，例如环境描写、人物情绪、对话张力、节奏控制。
2. 剧情拆解，例如装逼打脸、危机救场、误会反转、伏笔回收。
3. 用户后续手动创建的素材，第一阶段可以先不做独立手动创建入口。

## 与书库素材库的关系

小说内素材和书库素材库必须分离。

| 模块 | 数据归属 | 目的 | 数据来源 |
| --- | --- | --- | --- |
| 小说内素材 | 当前小说项目目录 | 展示和管理从本书沉淀出的素材 | 本书写作手法拆解、本书剧情拆解 |
| 书库素材库 | 书库目录 | 跨书检索当前书库素材，并保存书库自有素材 | 单书素材实时引用、书库自建素材、移除书籍前迁移素材 |

小说内素材是正式数据。复制小说项目目录时，本书素材必须跟随迁移。

书库素材页展示本书素材时默认读取单书项目目录中的正式数据，不复制第二份；但当用户从书库移除某本书时，系统必须先把该书已有素材迁移为书库自有素材，再删除单书项目目录，避免书库素材失效。书库素材库规则见 `docs/dev-guides/global-material-library.md`。

## 与拆解卡片的区别

| 对象 | 含义 | 是否可直接复用 | 来源 |
| --- | --- | --- | --- |
| 写作手法拆解卡片 | 对原文片段写法的分析记录 | 不一定 | 原文片段 |
| 剧情拆解卡片 | 对章节范围内剧情单元的分析记录 | 不一定 | 章节范围 |
| 小说内素材 | 用户二次整理后的写作知识 | 是 | 一个或多个拆解卡片 |

素材必须经过显式沉淀动作创建。不要把每张拆解卡片自动等同为素材。

## 沉淀为素材流程

写作手法拆解卡片和剧情拆解卡片详情中都应提供“沉淀为素材”入口。

推荐流程：

```text
打开拆解卡片
-> 点击沉淀为素材
-> 生成素材草稿
-> 用户编辑标题、原文、拆解说明和标签
-> 保存到当前小说项目目录
-> 书库素材页刷新时可通过单书引用看到该素材
```

沉淀规则：

1. 来源拆解卡片只提供初始内容，不强制用户原样保存。
2. 一个拆解卡片可以沉淀出多个素材。
3. 一个素材可以引用多个来源拆解卡片，后续用于归纳同类经验。
4. 素材必须保留来源引用和来源快照。
5. 删除拆解卡片时，不应直接删除已沉淀素材；应提示来源引用将失效或保留快照。

## 小说内素材页面

当前书工作区中的“素材”页面展示当前书项目目录里的素材。

页面职责：

1. 展示本书沉淀出的素材。
2. 支持按素材类型、标签、来源章节、来源拆解类型筛选。
3. 支持搜索标题、原文、拆解说明和来源快照。
4. 支持查看素材详情。
5. 支持编辑素材标题、原文、拆解说明和标签。
6. 支持跳转到来源原文、写作手法拆解卡片或剧情拆解卡片。
7. 支持删除素材。
8. 素材列表按创建时间排序，编辑素材后不应因为更新时间变化而跳到列表前面。
9. 素材详情应突出标题、拆解类型、维度、原文、拆解说明和标签；不要把页面做成复杂的摘要、正文、分类管理表单。

小说内素材页面不负责跨书聚合展示。跨书检索放到书库素材库。

## 素材类型

素材类型用于区分素材的复用方向，第一阶段建议至少支持：

| 类型 | 含义 |
| --- | --- |
| `writingTechnique` | 写作手法素材，例如环境描写、人物情绪、对话张力。 |
| `storyPlot` | 剧情结构素材，例如装逼打脸、误会反转、危机救场。 |

素材类型不等同于拆解类型。素材类型是素材库的一级归类，拆解类型是拆解方案中的分析口径。

## 数据结构

小说内素材建议保存在当前小说项目目录：

```text
books/{bookId}/
└── materials/
    ├── materials.json
    └── texts/
        └── material-20260824-0001.txt
```

示例：

```json
{
  "version": 1,
  "items": [
    {
      "id": "material-20260824-0001",
      "bookId": "book-20260824-001",
      "materialType": "storyPlot",
      "title": "装逼打脸桥段的四段式推进",
      "summary": "主角被当众压制后，用隐藏实力完成反转。",
      "contentPath": "materials/texts/material-20260824-0001.txt",
      "categoryIds": [],
      "tagIds": ["tag-face-slap", "tag-crowd-reaction"],
      "sourceRefs": [
        {
          "sourceKind": "storyPlot",
          "deconstructionId": "story-plot-20260824-0001",
          "sourceTextId": "",
          "chapterRefs": [
            {
              "chapterId": "chapter-000001",
              "chapterOrder": 1,
              "chapterTitleSnapshot": "第一章 初入江湖"
            }
          ],
          "snapshot": {
            "bookName": "某本小说",
            "deconstructionTitle": "第一次装逼打脸",
            "planTypeName": "装逼打脸",
            "dimensionName": "高潮反转",
            "sourceSummary": "主角被当众压制后完成反转。"
          }
        }
      ],
      "createdAt": "2026-08-24T10:30:00+08:00",
      "updatedAt": "2026-08-24T10:35:00+08:00"
    }
  ]
}
```

字段原则：

1. `materialType` 表示素材复用方向。
2. `title` 是素材标题。
3. `summary` 在写作手法素材中保存原文片段；剧情素材中可保存剧情简介。
4. `contentPath` 指向可直接阅读的拆解说明 TXT。
5. `tagIds` 支持多归属；`categoryIds` 为兼容字段，素材页面第一阶段不展示分类。
6. `sourceRefs` 可以引用一个或多个拆解来源。
7. 来源快照必须能在原书项目暂时不可用时支撑基本阅读。

## 来源追溯

素材来源必须支持两类拆解：

1. 写作手法拆解来源：回到书籍、章节、原文片段和写作手法拆解卡片。
2. 剧情拆解来源：回到书籍、章节范围和剧情拆解卡片。

来源引用必须同时保存可跳转 ID 和快照：

```text
可跳转 ID：bookId、chapterId、sourceTextId、deconstructionId
快照：书名、章节名、选中文本或剧情简介、拆解标题、创建时间
```

这样做是为了保证章节被改名、拆解卡片被删除或来源位置失效时，素材仍然可读，并能向用户说明来源状态。

## 与书库素材同步

小说内素材保存、更新或删除后，书库素材页应能在刷新时重新扫描当前书库中的单书素材。

规则：

1. 单书素材仍以小说项目目录为正式数据。
2. 书库素材页展示单书素材时使用实时引用，不直接改写或删除本书素材。
3. 移除书籍前必须把该书素材复制为书库自有素材，复制成功后才允许删除单书项目目录。
4. 下次打开书库素材库时，应允许从书库 `index.json` 中仍存在的小说项目重新扫描 `materials/materials.json`。

## 边界

第一阶段不做：

1. AI 自动整理素材。
2. 自动跨书合并相似素材。
3. 云同步素材库。
4. 多人协作素材库。
5. 跨设备实时同步。
