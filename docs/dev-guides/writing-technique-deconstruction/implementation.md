# 写作手法拆解模块指南

本文定义写作手法拆解模块的产品目的、页面交互、数据结构和实现边界。写作手法拆解关注用户从原文片段中分析“这段文字怎么写”，它不是剧情拆解，也不是素材库。

## 目的

写作手法拆解用于帮助用户在阅读小说时，选中一段原文并记录自己的写法分析。

典型问题：

1. 这段环境描写如何制造氛围。
2. 这段人物情绪如何递进。
3. 这段对话如何制造张力。
4. 这段动作、节奏、视角、伏笔有什么可学习的写法。

核心流程：

```text
阅读原文 -> 选中文字 -> 创建写作手法拆解 -> 选择类型 -> 选择维度 -> 填写看法 -> 保存卡片
```

## 与剧情拆解的区别

| 模块 | 分析对象 | 常见来源 | 表单颗粒度 | 结果 |
| --- | --- | --- | --- | --- |
| 写作手法拆解 | 原文片段 | 用户选中文字 | 类型、维度、一个看法输入区 | 写作手法拆解卡片 |
| 剧情拆解 | 剧情单元 | 一个或多个章节范围 | 剧情名称、剧情简介、类型、多个维度输入区 | 剧情拆解卡片 |

写作手法拆解必须从原文选区出发。剧情拆解不强制绑定单一原文片段，详细规则见 `docs/dev-guides/story-plot-deconstruction/implementation.md`。

## 页面入口

写作手法拆解有两个入口：

1. 阅读工作台中的选文拆解弹框，用于创建卡片。
2. 当前书工作区中的“写作手法拆解”页面，用于管理已有卡片。

阅读工作台只负责创建入口和来源上下文，不负责集中管理全部卡片。

## 选文创建弹框

用户在阅读 TAB 选中文字后，页面记录选文来源，并显示轻量浮动工具栏。点击“创建写作手法拆解”后打开弹框。

弹框结构：

```text
写作手法拆解弹框
├── 原文片段预览
├── 拆解类型选择 / 临时新增类型
├── 当前类型下的维度选择 / 临时新增维度
├── 用户自己的看法
├── 标签和分类入口
└── 取消 / 保存 / 保存并继续创建
```

交互规则：

1. 弹框内必须展示原文片段，避免用户脱离上下文填写。
2. 拆解类型和维度来自当前书 `writingTechnique` 模板。
3. 用户选择拆解类型后，只展示该类型下的维度。
4. 当前模板只是默认参考；如果阅读时想到新的分析口径，用户可以在弹框中临时新增或改名本次卡片的类型和维度。
5. 临时新增或改名的类型和维度只保存到本张卡片的快照字段，不自动改写当前写作模板。
6. 用户的分析正文统一保存在一个看法输入区，不再扩展成复杂字段表单。
7. 保存后创建写作手法拆解卡片，并保留来源追溯。
8. “保存并继续创建”允许同一原文片段继续创建另一张写作手法拆解卡片。
9. 弹框关闭后返回阅读位置，不改变当前阅读内容。

## 来源追溯

写作手法拆解必须引用原文片段。

页面记录：

1. `bookId`
2. `chapterId`
3. `chapterOrder`
4. `startOffset`
5. `endOffset`
6. `selectedText`

保存时应生成或复用 `SourceText`。同一段选文可以被多个写作手法拆解卡片引用，不要设计成一对一。

## 写作手法拆解卡片页

当前书工作区应提供“写作手法拆解”页面。

页面职责：

1. 展示当前书全部写作手法拆解卡片。
2. 支持按章节、拆解类型、维度、标签、关键词、创建时间筛选。
3. 支持查看卡片详情。
4. 支持编辑用户自己的看法、标签和分类。
5. 支持编辑卡片自己的类型和维度快照；即使该类型或维度已经不在当前模板中，也不能在编辑时被模板默认项覆盖。
6. 支持删除卡片。
7. 支持从卡片跳转回原文位置。
8. 支持从卡片沉淀为小说内素材。

页面不负责：

1. 不展示剧情拆解卡片。
2. 不做跨书聚合。
3. 不把卡片退化成普通自由笔记。
4. 不直接管理写作手法模板；模板管理在拆解方案页。

## 数据结构

写作手法拆解卡片建议保存在当前小说项目目录：

```text
books/{bookId}/
└── deconstructions/
    └── writing-technique-cards.json
```

示例：

```json
{
  "version": 1,
  "items": [
    {
      "id": "writing-technique-20260824-0001",
      "bookId": "book-20260824-001",
      "sourceTextId": "source-20260824-0001",
      "analysisKind": "writingTechnique",
      "planTypeId": "technique",
      "planTypeName": "表现手法",
      "dimensionId": "environment",
      "dimensionName": "环境描写",
      "content": "这段用雨声和灯光压低重逢情绪。",
      "tagIds": ["tag-atmosphere"],
      "materialIds": ["material-20260824-0001"],
      "createdAt": "2026-08-24T10:35:00+08:00",
      "updatedAt": "2026-08-24T10:35:00+08:00"
    }
  ]
}
```

字段原则：

1. `analysisKind` 固定为 `writingTechnique`。
2. `sourceTextId` 负责回到原文片段。
3. `planTypeId` 和 `dimensionId` 保存创建时的结构标识。
4. `planTypeName` 和 `dimensionName` 保存创建时展示名称快照。
5. `content` 保存用户自己的分析看法。
6. `materialIds` 记录从该卡片沉淀出的小说内素材。
7. 如果创建或编辑时使用模板外临时类型、临时维度，也沿用同一组 ID 和名称快照字段保存，不新增单独数据文件。
8. 修改模板不能批量改写历史卡片。

## 与素材库关系

写作手法拆解卡片可以沉淀为小说内素材。素材不是卡片换名，而是用户二次整理后的可复用写作知识。

沉淀为素材时，可以把原文片段、拆解类型、维度和用户看法作为素材草稿初始内容，但用户必须能编辑素材标题、原文、拆解说明和标签。

小说内素材的详细规则见 `docs/dev-guides/book-material-library/implementation.md`。

## 旧数据兼容

旧项目可能只有通用 `deconstruction-cards.json` 或旧字段结构。

迁移原则：

1. 如果旧卡片来自原文选区，迁移为 `writing-technique-cards.json`。
2. 如果旧卡片没有 `sourceTextId`，应根据旧的书籍、章节和原文位置创建 `SourceText`。
3. 旧 `fieldValues` 不应丢失，可以作为历史内容摘要展示。
4. SQLite 索引损坏时，写作手法拆解列表必须能从 `writing-technique-cards.json` 和 `source-texts.json` 重建。

## 边界

第一阶段不做：

1. AI 自动写拆解。
2. 自动识别写作手法。
3. 跨书写作手法对比。
4. 把写作手法拆解做成复杂字段表单。
5. 把写作手法模板临时修改写回历史卡片。
