# 阅读工作台设计原则

本文约束阅读工作台的产品目的、交互原则和实现边界。阅读工作台是用户进入单本小说后最核心的工作区，必须同时服务“专注阅读”和“选文拆解”，不能退化成普通阅读器或普通笔记页。

## 目的

阅读工作台负责承接用户打开一本小说后的主要工作流：

```text
打开小说 -> 恢复上次阅读位置 -> 阅读原文 -> 选中文字 -> 创建拆解 -> 保存拆解卡片 -> 沉淀素材
```

核心目标：

1. 用户从书库点击小说时，默认打开该小说上次阅读到的位置。
2. 用户从应用内进入阅读工作台时，默认恢复当前书的最近阅读位置。
3. 阅读正文始终是页面主区域，章节目录和拆解表单都不能长期挤占阅读空间。
4. 用户选中文字后可以快速创建拆解，拆解表单以弹框方式出现。
5. 阅读模式和编辑模式通过同一工作台内的两个 TAB 切换。
6. 章节目录通过右侧目录按钮打开，目录内容分页展示，并默认定位到当前章节所在页。
7. 阅读内容通过“上一页 / 下一页”切换，不把大量章节标题铺在阅读区上方。

## 设计原则

1. 阅读优先：阅读正文时不要默认展示大面积章节列表、拆解表单或复杂统计。
2. 选文优先：创建拆解必须从选中文字出发，路径要短，但表单不常驻页面下方。
3. TAB 分离状态：阅读和编辑是同一工作台下的两个 TAB，避免编辑控件干扰普通阅读。
4. 目录轻量可召回：章节目录放在右侧目录按钮中，按页展示，不作为页面左侧常驻栏。
5. 当前章节定位：如果当前阅读到第 302 章，目录弹层打开时必须显示第 302 章所在目录页，并允许前后翻目录页。
6. 内容分页阅读：阅读区域应提供左侧上一页、右侧下一页的稳定操作区，点击后加载不同阅读内容。
7. 拆解弹框化：用户选中文字并点击创建拆解后，打开拆解弹框；不在正文下方展开大型拆解表单。
8. 来源可追溯：任何从选文创建的拆解，都必须保存书籍、章节、原文位置和选中文本范围。
9. 一段多拆解：同一段原文允许创建多个拆解卡片，不能设计成原文片段和拆解一对一。
10. 本地正式数据优先：阅读位置、章节修正文、拆解和素材正式数据都属于单本小说项目目录。

## 功能边界

阅读工作台负责：

1. 恢复和保存当前书阅读位置。
2. 展示当前阅读内容页或当前章节内容。
3. 提供上一页、下一页、目录跳转、搜索定位等阅读导航。
4. 提供阅读 / 编辑 TAB。
5. 在编辑 TAB 中修改章节标题和章节正文。
6. 处理文本选择，并显示轻量浮动工具栏。
7. 通过弹框创建拆解卡片。
8. 保存拆解后继续阅读、继续为同一片段创建拆解，或沉淀素材。

阅读工作台不负责：

1. 不在顶部分页展示章节标题。
2. 不常驻展示完整章节目录。
3. 不在正文下方展开拆解工作台。
4. 不把拆解字段写死成固定模板。
5. 不把素材库、分析图表或跨书比较塞进阅读工作台。
6. 不把阅读位置只保存到应用系统数据目录。
7. 不把 SQLite 索引缓存作为阅读位置或拆解数据的唯一来源。

## 与其他模块关系

1. 书库模块只负责打开小说入口；点击小说后应把小说项目目录传给当前书工作区，由阅读工作台恢复上次位置。
2. 章节识别和初始章节正文来自导入模块；章节标题和正文修正发生在阅读工作台编辑 TAB。
3. 拆解方案来自当前书的拆解方案模块；拆解弹框必须按当前书方案动态渲染字段。
4. 拆解卡片和素材库负责后续管理；阅读工作台只提供创建入口和来源上下文。
5. 全局设置可以保存字号、主题、窗口偏好等应用偏好，但单本书阅读位置应保存在小说项目目录中。
