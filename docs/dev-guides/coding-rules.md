# 编码与注释规则

本文用于约束后续 AI 和开发者的代码组织、注释和协作方式。

## 总体原则

1. 先按现有代码风格开发。
2. 不做与当前任务无关的重构。
3. 不为了未来想象场景创建复杂抽象。
4. 页面、业务、存储职责分清。
5. 新增依赖必须有明确必要性。
6. 所有核心数据默认保存在本地小说项目目录。
7. 小说正文、拆解长文本和素材正文保存为 TXT。
8. 系统结构化数据保存为 JSON，便于按代码数据结构序列化和反序列化。
9. 只有系统全局设置和全局素材引用索引才保存到应用系统数据目录。
10. SQLite 只能作为可重建索引缓存，不能作为唯一正式数据源。

## 文件注释

新增源码文件必须在文件顶部添加文件注释，说明该文件负责什么。

示例：

```go
// Package importbook 负责本地小说文件导入和章节识别。
```

或：

```ts
// ReadingPage renders chapter text and starts text-selection deconstruction flows.
```

## 模块注释

新增模块、包或目录应有简短说明，说明边界和职责。

适合写在：

1. Wails Go 后端模块注释
2. 前端模块入口文件
3. 目录 README
4. 重要 service 文件顶部

模块注释要回答：

1. 这个模块负责什么。
2. 它不负责什么。
3. 它依赖哪些核心模型或服务。

## 函数注释

以下函数必须写注释：

1. 导出函数。
2. 复杂业务函数。
3. 有副作用的函数，如写项目数据文件、刷新索引缓存、批量导入。
4. 章节识别、位置映射、数据迁移等容易误解的函数。

函数注释要说明业务意图，不要重复函数名。

示例：

```ts
/**
 * Splits imported novel text into editable chapter candidates.
 * The result is only a draft until the user confirms it.
 */
export function detectChapters(text: string): ChapterCandidate[] {
    // ...
}
```

## 功能注释

复杂功能块应添加短注释，尤其是：

1. 章节识别规则。
2. 原文位置计算。
3. 一个原文片段绑定多个写作手法拆解。
4. 剧情拆解非连续章节范围解析。
5. 小说内素材和书库素材库的来源追溯。
6. 数据迁移。
7. 导入事务。

注释应该解释为什么这样做，而不是描述代码逐行做了什么。

## 命名规则

命名优先反映业务概念：

1. book 表示书籍。
2. chapter 表示章节。
3. sourceText 表示原文片段或原始文本。
4. writingTechnique 表示写作手法拆解。
5. storyPlot 表示剧情拆解。
6. deconstruction 表示拆解体系的通用概念。
7. plan 表示拆解方案。
8. material 表示素材。
9. category 表示分类。
10. tag 表示标签。

不要把写作手法拆解卡片、剧情拆解卡片或素材命名为普通 note，避免产品退化成笔记软件。

## 数据修改规则

涉及本地数据结构变更时必须：

1. 说明新增字段业务含义。
2. 考虑旧数据迁移。
3. 考虑备份和恢复。
4. 保证来源追溯不丢失。
5. 保证一个原文片段可以有多个写作手法拆解。
6. 明确该数据属于小说项目目录还是应用系统数据目录。
7. 明确该数据应保存为 TXT 还是 JSON。
8. 如果是跨书快捷索引，必须能从小说内素材和书库自有素材正式数据重建。

## 前端开发规则

1. 阅读工作台优先保证正文可读。
2. 选文创建写作手法拆解路径要短。
3. 写作手法拆解类型和维度由写作手法模板驱动。
4. 剧情拆解类型和初始维度由剧情模板驱动，但卡片内临时维度修改不自动改写模板。
5. 不在组件中硬编码固定拆解类型或维度。
6. 保存失败、未保存、加载中状态必须可见。
7. 剧情拆解弹框关闭前必须处理未保存修改和草稿。
8. 不把复杂业务规则散落在多个组件中。

## 后端开发规则

1. 文件导入和项目数据写入要有明确错误处理。
2. 批量写入尽量使用事务。
3. 章节识别结果必须可被用户修正。
4. 原始文本和用户修正文分开保存。
5. API 输入输出保持稳定结构。
6. 搜索和筛选逻辑优先放在后端服务层。
7. SQLite 索引缓存必须能从项目目录中的正式数据重建。
8. 单本小说的正式数据必须写入用户选择的小说项目目录。
9. 全局主题、窗口、最近项目等应用级设置和可重建缓存才写入应用系统数据目录。
10. 小说内素材正式数据必须写入小说项目目录，书库自有素材正式数据必须写入书库目录，不能只写入应用级缓存。

## 文档更新规则

当新增核心模块时，至少更新：

1. `docs/dev-guides/index.md`
2. 对应模块指南

当改变产品原则、MVP 边界或技术选型时，同时更新：

1. `docs/ai-guides/product-brief.md`
2. `docs/dev-guides/tech-stack.md`
