# 书库设计原则

本文约束书库和小说导入模块的产品目的与实现边界。

## 目的

书库负责管理用户本地小说集合。它不是云书架，也不是普通阅读器书单，而是本地拆书工作的入口。

核心目标：

1. 用户设置一个本地书库目录。
2. 每导入一本小说，就在书库目录下生成一个独立小说目录。
3. 导入文件复制进该小说目录，后续分析基于这份副本。
4. 每本小说拥有自己的 JSON 数据文件。
5. 书库根目录只维护轻量 `index.json`，用于快速展示书库列表。

## 设计原则

1. 书库目录由用户选择，不默认把小说正式数据放到应用系统目录。
2. 导入是“复制入库”，不是引用原始文件路径。
3. 每本小说目录必须完整、可复制、可迁移。
4. 一本小说的正式数据以该小说目录内的 TXT 和 JSON 为准。
5. 章节识别结果可以有几千章，页面必须分页展示章节标题，不要求用户逐章确认。
6. 导入阶段只允许修改小说名和简介，不编辑章节标题或正文。
7. 章节标题和正文修改放在小说打开后的阅读工作台编辑 TAB 中。
8. 确认导入后写入小说 JSON；后续打开小说以该 JSON 为入口。
9. `index.json` 只保存书库列表所需的最小信息，不保存章节、拆解或素材详情。

## 不做的事

1. 不做账号、云同步、多人协作。
2. 不把书库做成跨设备数据库。
3. 不要求导入时完成拆解方案配置。
4. 不在书库列表中展示复杂分析。
5. 不把 SQLite 作为唯一正式数据源。
