# 技术选型指南

本文记录当前阶段的技术方向。后续实现以本地 PC 产品为前提，不按 Web SaaS 思路设计。

## 产品形态

佳依拆书是 PC 端本地产品：

1. 数据默认保存在用户本机。
2. 第一阶段不设计账号系统。
3. 第一阶段不设计云同步。
4. 第一阶段不依赖远程服务完成核心功能。
5. 导入、阅读、拆解、素材管理必须离线可用。
6. 用户新建的小说目录必须是完整项目目录，复制到另一台电脑后仍可被本软件打开。
7. 单本小说相关正式数据必须全部存放在用户选择的小说项目目录中。
8. 小说正文和用户需要直接阅读的长文本保存为 TXT。
9. 系统结构化数据保存为 JSON。
10. 系统全局设置和全局素材引用索引才保存到应用系统数据目录。

## 推荐技术栈

当前考虑使用：

```text
Wails + Vue 3
```

推荐分工：

1. Wails：负责桌面壳、窗口能力、Go 后端与 Vue 3 前端桥接、前端资源打包。
2. Vue 3：负责页面、交互、阅读体验、配置表单、素材管理视图。
3. Go 后端：负责文本解析、章节识别、项目目录读写、索引缓存、搜索与导入导出。
4. 项目数据文件：小说长文本使用 TXT，结构化业务数据使用 JSON。
5. SQLite：只能作为打开小说目录时构建的索引和快捷查询缓存，不能作为唯一正式数据源。

## Wails 与 Vue 3 的边界

Wails 侧应保持清晰边界：

1. 提供窗口和系统能力。
2. 通过 Go 后端提供本地文件、项目目录和可重建索引缓存访问能力。
3. 处理必要的本地文件选择、系统交互和前后端绑定。

Go 后端负责稳定业务逻辑：

1. 书籍导入
2. 章节识别
3. 原文保存
4. 拆解方案保存
5. 写作手法拆解卡片保存
6. 剧情拆解卡片保存
7. 小说内素材库查询
8. 全局素材索引查询和重建
9. 分类和标签管理
10. 数据导入导出

Vue 3 前端不要直接写核心业务数据，除非只是临时 UI 状态。核心数据读写应通过 Wails 暴露的 Go 方法或明确的本地服务接口完成。

## 本地存储建议

优先采用用户选择的小说项目目录保存单本小说的正式数据。项目目录必须能直接复制、备份、版本管理，并在另一台电脑上被本软件重新打开。

正式数据格式按数据性质选择：

1. TXT：保存小说正文、导入原文、用户修正后的正文、拆解后需要给用户直接阅读的长文本内容、素材正文。
2. JSON：保存系统结构化数据，如书籍信息、章节元数据、拆解方案、拆解模板、拆解类型、拆解维度、写作手法拆解卡片元数据、剧情拆解卡片元数据、素材元数据、分类、标签、用户通过系统增删改产生的数据。
3. Markdown：不作为第一阶段正式主存储格式；后续如需使用，优先作为导出文件或用户可读的派生内容。

全局应用设置不放进某一本小说项目目录，只有系统级偏好才保存到应用系统数据目录，例如：

1. 主题颜色
2. 窗口大小和位置
3. 最近打开的小说项目列表
4. 应用级快捷键偏好
5. 全局素材引用索引
6. 与具体小说无关的全局配置

SQLite 可以引入，但只能作为缓存层：

1. 打开小说目录时，根据 JSON 和 TXT 构建或刷新 SQLite 索引。
2. SQLite 可用于全文搜索、筛选、统计、排序等快捷查询。
3. SQLite 文件可以删除，删除后必须能从项目目录中的正式数据重新生成。
4. 不允许只把正式数据写入 SQLite。
5. 不允许要求用户通过“软件导出”才能拿到自己的数据。
6. 备份和迁移应以复制小说项目目录为主，而不是导出数据库。

建议保存的数据类型：

1. 书籍基础信息
2. 原始文本文件记录
3. 章节
4. 用户修正后的章节正文
5. 拆解方案
6. 拆解模板
7. 拆解类型
8. 拆解维度
9. 原文片段位置和引用信息
10. 写作手法拆解卡片元数据
11. 剧情拆解卡片元数据
12. 小说内素材元数据
13. 全局素材引用索引
14. 分类
15. 标签
16. 拆解长文本内容

原始导入文件可以保存为项目目录内的 TXT 文件副本。正式元数据保存在 JSON 文件中。索引缓存中可以保存路径、哈希和查询字段，但缓存不是正式数据源。

## 小说项目目录建议

一个小说项目目录建议包含：

```text
book-project/
├── book.json
├── original/
│   └── imported.txt
├── chapters/
│   ├── chapter-0001.txt
│   └── chapter-0002.txt
├── plans/
│   └── current-plan.json
├── deconstructions/
│   ├── writing-technique-cards.json
│   ├── story-plot-cards.json
│   └── texts/
│       └── card-0001.txt
├── materials/
│   ├── materials.json
│   └── texts/
│       └── material-0001.txt
├── tags.json
├── categories.json
└── .cache/
    └── index.sqlite
```

`.cache/` 目录只保存可重建缓存，不参与正式数据迁移判断。

应用系统数据目录只保存全局应用数据和全局素材引用索引，不保存某一本小说的正式拆书数据。

## 数据原则

1. 原始文本和用户修正文要分开保存。
2. 原文片段和写作手法拆解卡片不是一对一关系，一个片段允许多个拆解。
3. 剧情拆解以章节范围为主要来源，必须支持非连续章节范围。
4. 小说内素材必须保留来源引用。
5. 全局素材库只保存跨书引用索引和快照，不能替代小说内素材正式数据。
6. 拆解方案属于书籍，也可以另存为模板。
7. 分类和标签支持多归属，不按单一文件夹模型设计。
8. TXT 保存需要用户直接阅读的小说、拆解长文本和素材正文。
9. JSON 保存系统结构化数据，与代码中的数据结构序列化和反序列化对应。
10. 单本小说数据不得散落到应用系统数据目录。
11. SQLite 索引只能从正式数据派生，不能反向成为唯一事实来源。

## 依赖原则

1. 优先使用成熟、轻量、可长期维护的依赖。
2. 不为少量代码引入大型框架。
3. 文本解析、JSON 序列化/反序列化、JSON Schema 校验、全文搜索和 SQLite 索引缓存可以使用稳定库。
4. 不引入云服务 SDK，除非需求明确提出。
5. 每个新增依赖都要说明用途和替代方案。
